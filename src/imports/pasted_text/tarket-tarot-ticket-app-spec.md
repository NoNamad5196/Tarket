Tarket이라는 한국어 타로 티켓 웹앱의 고품질 반응형 UI와 인터랙티브 프로토타입을 만들어줘.

1. 서비스 컨셉

Tarket은 Tarot + Ticket을 합친 이름이다.
사용자가 이름, 생년월일, 운세 카테고리를 입력하면 수정구슬에서 오늘의 타로 결과가 영화관 티켓처럼 발권된다.

가장 중요한 가치는 “오늘의 운세를 한 장의 티켓으로 받는 경험”이다.
극장에 입장하는 기대감, 수정구슬을 바라보는 설렘, 티켓을 직접 열어보는 순간이 자연스럽게 이어져야 한다.

소개용 랜딩페이지가 아니라 실제로 입력하고 결과를 확인할 수 있는 서비스 화면을 디자인해줘.
모든 주요 UI 문구는 한국어로 작성하고, Tarket / Tarot + Ticket / 카드 영문명만 영어를 사용해줘.

2. 전체 디자인 방향

키워드:
보라색 벨벳 커튼, 작은 프라이빗 극장, 신비로운 수정구슬, 고급 종이 티켓, 섬세한 금박, 은은한 별빛.

권장 색상:
- 배경: 블랙 퍼플 #100A1C
- 표면: 딥 플럼 #241335
- 메인: 퍼플 #7652B5
- 보조: 라벤더 #C4AFE8
- 포인트: 샴페인 골드 #D8BD88
- 주요 텍스트: 웜 화이트 #F5F0FA
- 보조 텍스트: 밝은 회보라 #BBAFCB

배경은 어두운 보라색 그라데이션으로 깊이를 만들고, 수정구슬 주변에만 빛을 집중해줘.
골드는 얇은 테두리, 작은 장식, 티켓 구분선에 절제해서 사용해줘.
커튼에는 부드러운 주름과 벨벳 질감을, 티켓에는 미세한 종이 질감을 표현해줘.

로고와 큰 제목에는 우아한 세리프를, 입력창과 본문에는 읽기 좋은 한국어 산세리프를 사용해줘.
Noto Serif KR와 Pretendard 또는 유사한 조합을 사용하고, 본문 가독성을 우선해줘.

유치한 점집 이미지, 과한 네온, 공포스러운 다크 판타지, 개발자 밈의 과도한 사용은 피해야 한다.

3. 화면 구성과 사용자 흐름

다음 다섯 장면을 하나의 연결된 경험으로 만들어줘.

A. 첫 진입 — 닫힌 커튼

화면 전체를 깊은 보라색 벨벳 커튼이 덮는다.
중앙 틈 사이로 아주 은은한 보라색과 금색 빛이 새어 나온다.

중앙에 다음 요소를 배치해줘.
- Tarket 로고
- 작은 “Tarot + Ticket”
- “오늘의 당신을 위한 한 장의 티켓.”
- 주요 버튼 “입장하기”

이 장면에서는 입력 폼을 노출하지 않는다.
입장 버튼이나 커튼을 클릭하면 커튼이 양옆으로 열리고, 뒤에 있던 수정구슬과 입력 영역이 드러난다.
열린 커튼 일부는 화면 가장자리에 남아 무대의 프레임처럼 작동한다.

B. 예매 — 사용자 정보 입력

메인 카피:
“당신의 운세를 예매해보세요.”

보조 문구:
“이름과 생년월일을 입력하면,
오늘의 운세가 한 장의 티켓으로 발권됩니다.”

데스크톱에서는 왼쪽에 수정구슬과 카피, 오른쪽에 절제된 입력 패널을 배치해줘.
모바일에서는 카피, 작은 수정구슬, 입력 폼 순서로 구성해줘.

입력 항목:
- 이름: 라벨을 항상 표시하고, 예시 “이름을 입력해주세요”
- 생년월일: 연·월·일을 명확하게 입력할 수 있는 형태
- 운세 카테고리: 아래 여섯 가지 중 하나 선택

카테고리:
- 오늘의 운세
- 연애운
- 금전운
- 공부운
- 인간관계운
- 개발운

카테고리는 2열 × 3행의 선택 버튼으로 구성해줘.
작고 일관된 선형 아이콘을 사용하고, 선택 상태는 테두리·배경·체크 표시로 명확하게 표현해줘.
개발운에는 작은 코드 괄호 심볼을 넣어 서비스의 개성을 보여줘.

주요 CTA:
“타로 티켓 예매하기”

하단 안내:
“같은 정보와 같은 운세로 예매하면, 오늘은 같은 티켓을 받습니다.”

필수 항목 누락과 잘못된 생년월일은 해당 입력창 바로 아래에 짧은 한국어 문구로 안내해줘.
아직 카테고리를 고르지 않은 상태도 포함해줘.

C. 발권 중 — 수정구슬 연출

예매 버튼을 누르면 입력 영역이 부드럽게 사라지고 수정구슬이 화면 중심으로 이동한다.

수정구슬은 빛을 품은 반투명 유리 재질로 표현해줘.
구슬 내부의 안개와 별빛이 천천히 회전하고, 양옆의 섬세한 손 일러스트가 작은 폭으로 움직인다.
손은 공포스럽거나 과장된 모습이 아니라 우아한 마술사의 제스처처럼 표현해줘.

주변에는 적은 수의 파티클과 은은한 보라색 빛이 나타난다.

문구:
“당신의 오늘을 티켓에 새기는 중…”

이 장면은 수정구슬의 움직임이 로딩 상태를 전달하도록 구성해줘.
발권 중 중복 클릭은 방지해줘.

D. 발권 완료 — 아직 열지 않은 티켓

수정구슬 하단의 받침대에 가느다란 발권구가 빛나며 나타난다.
그 안에서 영화관 티켓 한 장이 아래로 천천히 밀려 나온다.

티켓에는 다음 요소만 먼저 보여줘.
- Tarket
- 사용자 이름
- 선택한 운세 카테고리
- 발권 날짜
- 작은 장식용 일련번호
- “당신의 오늘이 도착했습니다.”

카드명과 상세 운세는 아직 공개하지 않는다.

주변 안내:
“티켓을 눌러 오늘의 운세를 펼쳐보세요.”

티켓 전체를 클릭 가능한 대상으로 만들고, 데스크톱에서는 hover 시 살짝 들리는 효과를 적용해줘.
모바일에서는 터치 가능한 버튼이라는 점이 분명히 드러나게 해줘.

E. 결과 — 펼쳐진 타로 티켓

티켓을 누르면 중심으로 확대되며 상세 운세가 펼쳐진다.
결과 화면의 주인공은 큰 영화관 티켓이다.

티켓의 형태:
- 양옆 반원형 홈
- 점선 절취선
- 얇은 금박 테두리
- 카테고리별 작은 문양
- 티켓 본문과 스텁을 나누는 명확한 구획
- 작은 발권 날짜와 일련번호
- 배경에서 자연스럽게 떠오르는 부드러운 그림자

데스크톱에서는 가로형 티켓으로, 주요 운세 본문과 카드 아트가 있는 스텁을 구분해줘.
모바일에서는 같은 디자인 언어를 유지한 세로형 티켓으로 재배치해줘.
긴 본문이 잘리거나 지나치게 작은 글자가 되지 않도록 높이가 자연스럽게 늘어나게 해줘.

정보 순서:
1. 카테고리 / 사용자 이름 / 발권 날짜
2. 카드 아트와 카드명
3. 오늘의 키워드
4. 운세 제목
5. 한 줄 요약
6. 상세 해석
7. 오늘의 조언
8. 주의할 점
9. 행운 요소

운세 제목과 한 줄 요약을 가장 먼저 읽게 해줘.
조언, 주의할 점, 행운 요소는 간결한 구획으로 나눠줘.

티켓 아래 버튼:
- 주요 버튼 “다른 운세 예매하기”
- 보조 버튼 “티켓 다시 펼치기”

다른 운세를 선택할 때 이름과 생년월일은 유지해줘.
같은 조건으로 다시 열면 기존 티켓이 그대로 표시되어야 한다.

4. 결과 화면에 사용할 샘플 콘텐츠

아래는 디자인 확인용 예시 데이터다.

사용자: 지우
카테고리: 개발운
카드: The Star · 별
키워드: 회복과 가능성
제목: 막혔던 코드가 풀리는 날
요약: 오래 붙잡던 문제가 의외로 작은 곳에서 풀릴 수 있어요.
상세 해석: 복잡하게만 보였던 흐름을 한 걸음 떨어져 살펴보세요. 익숙한 코드를 다시 읽는 시간이 새로운 해결의 실마리가 될 수 있어요.
오늘의 조언: 새 기능을 더하기 전에, 기존 코드를 천천히 읽어보세요.
주의할 점: 한 번에 많은 부분을 바꾸기보다 작은 단위로 확인해보세요.
행운 요소: 작은 커밋

카드 아트는 별과 가느다란 궤도선을 활용한 독창적이고 섬세한 일러스트로 표현해줘.
운세 문장은 부드러운 조언으로 작성하고, 미래를 확정하거나 불길한 예언을 하지 않아야 한다.

5. 카테고리별 티켓 변형

티켓의 기본 레이아웃은 공통으로 유지하고, 작은 문양과 포인트 색상에 차이를 줘.

- 오늘의 운세: 별, 달, 운명선 / 라벤더
- 연애운: 장미, 작은 하트 / 로즈 퍼플
- 금전운: 코인, 섬세한 기하 문양 / 샴페인 골드
- 공부운: 책, 별빛, 집중선 / 연보라
- 인간관계운: 연결선, 별자리, 리본 / 모브
- 개발운: 코드 괄호, 작은 커밋 노드 / 실버 라벤더

개발운도 전체의 고급스러운 분위기를 유지해야 한다.

6. 인터랙션과 상태

권장 모션:
- 커튼 열림: 약 1.2초, 부드러운 감속
- 수정구슬 발권 연출: 약 2~3초
- 티켓 배출: 약 0.8초
- 티켓 펼침: 약 0.5초

움직임은 기대감을 만들되 사용자를 오래 기다리게 하지 않도록 해줘.
모션 감소 설정에서는 회전과 큰 이동을 줄이고 짧은 페이드로 대체해줘.

다음 상태를 포함해줘.
- 입력 전 / 입력 완료
- 입력 오류
- 카테고리 선택 / 미선택
- 발권 중
- 티켓 배출 완료
- 결과 공개
- 결과를 불러오지 못했을 때 재시도
- 긴 이름과 긴 운세 문구가 들어오는 경우

프로토타입은 샘플 데이터로 전체 흐름을 체험할 수 있게 해줘.
실제 AI API 연결 없이도 완결되어야 한다.
동일한 이름·생년월일·날짜·카테고리는 동일한 결과를 보여주고, 반복 클릭만으로 다른 결과가 나오면 안 된다.

서비스의 설정은 생년월일과 오늘 날짜를 바탕으로 계산한 운세 재료를 문장으로 표현하는 방식이다.
정통 사주 서비스로 표현하지 말고, 계산식·seed·API 등 구현 용어는 사용자 화면에 노출하지 않아야 한다.

7. 반응형과 제작 요구사항

- 데스크톱 1440px, 모바일 390px 기준 화면을 만들어줘.
- 작은 모바일에서도 가로 스크롤 없이 사용할 수 있게 해줘.
- 모바일 버튼과 선택 항목의 터치 영역은 최소 44px로 확보해줘.
- 본문은 모바일에서도 16px 전후로 읽기 편하게 구성해줘.
- 입력창 라벨, 키보드 포커스, 명확한 선택 상태를 제공해줘.
- 색상만으로 선택이나 오류를 구분하지 않도록 해줘.
- Auto Layout과 재사용 가능한 컴포넌트로 구성해줘.
- 버튼, 입력창, 카테고리 선택, 티켓의 상태를 일관되게 정의해줘.
- 커튼 → 입력 → 발권 → 티켓 클릭 → 결과 → 다른 운세 선택 흐름을 연결해줘.

MVP 범위에는 회원가입, 결제, SNS 공유, 이미지 저장, 티켓 보관함, 월간 리포트를 넣지 않는다.

가장 높은 시각적 완성도가 필요한 부분은 커튼이 열리는 첫 장면, 빛을 품은 수정구슬, 발권되는 티켓, 펼쳐진 결과 티켓이다.
이 네 요소가 하나의 극장 경험처럼 이어지도록 디자인해줘.
